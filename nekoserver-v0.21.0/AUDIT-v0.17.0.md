# NekoServer v0.17.0 audit

743 Python tests, 32 Rust tests and 90 release checks passed. Rust formatting and Clippy with warnings denied passed. Exact output and limits are in audit-evidence/EVIDENCE-NOTES.md.

The storage policy is now SSD music and Immich live assets, independent HDD music/photo backups, and HDD-only movies/shows/downloads. Navidrome, Lidarr, qBittorrent music paths, local imports and onboarding use the SSD; existing container paths remain stable. Monthly snapshots/rehearsal/rollback and explicit Immich recovery use the SSD original tree. Monthly payloads include SSD music; HDD movie and show files remain excluded. A Rust nightly music worker stores immutable verified content with versioned inventories and no automatic deletion. The ad hoc Python music-recovery.py verifies/restores a selected inventory into a new directory. Backup reports, dashboard, acceptance, permissions and the full-profile dependency plan are connected.

The native guarded SATA policy supports idle timers in 30-minute steps (default 60) plus keep_spinning/unchanged. It only configures the verified physical media HDD and does not suspend the PC. SMART polling avoids waking standby disks. Default photo archival is every six hours, with a correspondingly longer unarchived-upload window, plus retained nightly SQL/weekly external/monthly full protection. Nextcloud, media/torrent/scanner/backup activity can still wake the HDD. The policy cannot promise drive sleep, wake latency or lifespan.

Existing old HDD music/Immich manifests are preserved and refused until a verified stopped-writer migration is performed. An old-version maintenance recovery journal is preserved and refused so a changed layout cannot be applied to it. No existing user data is moved/deleted by installation. See STORAGE.md for exact locations, schedules, recovery and upgrade requirements. Physical installation, upstream container startup/migrations, real clients/connections/playback, permissions/ACL/sandbox, HDD standby/wake, USB behavior and independent disaster recovery still require acceptance on the intended PC. This is a tested software release, not a claim that the server has already been deployed.
